# Plans of 2026-11-12: free smart mode, 3D-NR, echo cancellation

Read-only analyses (Fable), checked against the code by the coordinating agent. Owner's decisions of 2026-11-12:
1. implement the free smart mode **and wire the existing `vbr` / `smart` settings of `rtspserver.conf` to the free
   encoder** (they do nothing since 3.0.1-rc34);
2. 3D-NR at 1080p if a larger CMA can be had without touching U-Boot, else at 720p;
3. echo cancellation implemented behind a switch (default off); everything ships in the next RC, tested there.

Line numbers are those of 2026-11-12 (HEAD `1abd9c4`); re-locate before editing.

## 1. Free encoder: VBR and smart mode (`[fe-smart]`)

**Facts.**
- `src/h265enc/freeenc.h:259`: fixed GOP (`frame % gop == 0`); `force_idr` only after a failed picture.
- `src/h265enc/rc.h`: one QP per picture from a virtual buffer (CBR-like), ±3 per P, IDR at P QP − 2, clamp to
  [qmin, qmax]. On a still scene the QP sits at qmin.
- `src/tc100rtsp/tc100_rtsp.c:193`: `pa->rc_vbr` is never passed to `fe_open_wh`, so VBR does nothing.
- `tc100_rtsp.c` ~3009-3070: `smart_apply` / `p_smart` call the vendor `ak_venc_set_smart_config` (gone since rc34;
  `p_smart = NULL` at ~269). The vendor smart mode is software inside the closed library; mode 1 looked like a long-term
  reference (one more 1080p frame buffer: does not fit the 9600K pool).
- `v3/linux66-sd/rtsp-launch.sh:113-121`: `rtspserver.conf` `[0] vbr / smart` are the single source; `RTSP_VBR` /
  `RTSP_SMART` in `rtsp.env` are ignored and overwritten from the config.
- Constraints: GOP cache 128 frames / 1536 KB (`tc100_rtsp.c:75-77`); a joining or lossy client waits for the next IDR
  (`wait_idr`, ~2314, 2321, 2436-2438, 3885); the recorder starts/rotates on a keyframe and `FRAG_MAX_SAMPLES 128`
  (`rec.c:73, 723-746`); the thumbnail assumes a fixed GOP (`tc100_rtsp.c:3912`); the browser fMP4 viewer drops after
  10 s without a keyframe (`livemp4.c:42`); POC fits 10 bits below 512 frames (`slicehdr.h:57`), H.264 `frame_num` 4 bits.
- Motion: `md_on && !md_motion` (8 s hysteresis, ~2728); sound events `snd_t`.

**Design.**
- **VBR (`vbr=1`)**: quality-first rate control: the QP aims at a quality target and only rises when the bit rate
  exceeds the configured kbps (ceiling, not target). Define it in `rc.h` next to the current mode; CBR stays the
  default and is unchanged.
- **Smart (`smart=1`, meaningful with VBR as on the vendor firmware; decide and document whether smart without VBR is
  allowed)**: on a still scene the GOP grows up to `gop_long` (default 250, ≤ 300) and the QP floor is
  `min(qmax, qmin + 4)`; on motion, the floor goes at once and the next IDR comes at the base GOP. IDR rule:
  `idr = frame==0 || force_idr || frame >= gop_long || (frame >= gop && (!still || idr_want))`, so never more IDRs than
  today and no client waits longer than the base GOP. `idr_want` is set wherever `wait_idr = 1` is set.
- v1 keeps the fixed GOP on the recorded stream while recording is configured and while the browser live view
  (`live_wants`) is active, so `rec.c` and `livemp4.c` keep their invariants. Thumbnails use `fe_next_idr`.
- `smart=2` (vendor mode 2) has no free equivalent: treat as 1 and log it. Optional overrides in `rtsp.env`:
  `RTSP_FE_SMART_GOP`, `RTSP_FE_SMART_QP` (new names, not overwritten by the launcher).
- Remove the dead vendor `smart_apply` / `p_smart` path once the tests that mention it are updated.

**Camera check first**: H.265 and H.264 at `-g 300` on the free encoder for 30 min.
**Gain (EST)**: −25 to −40 % bit rate on a still scene, 5x fewer IDR bursts, no CPU.
**Not now**: ROI, intra refresh, long-term reference: need register traces of the vendor library (rc33 SD card,
`src/h265enc/venctrace`, `v3/dev/h265-step2.sh trace`).

## 2. 3D-NR (`[nr3d]`)

**Facts.**
- Patch 0006 `alloc_ref()` (~10409-10426): reference hard-coded 1920x1080, 3 bytes/pixel = 6075 KiB (Y 4050 + UV 2025),
  at probe only when `ak39_vi.nr3d=1` (0444, default 0).
- `program_ref()` (~10428-10444) programs `vi->width*vi->height` (the output size) at every stream start, but the TNR
  block follows the crop (`ak_isp_vi_set_crop`, ~1294-1336) and patch 0016 fixes the crop at 1920x1080 for every
  format: at a 720p main it declares a 720p reference to a block working at 1080p (latent bug). The reference therefore
  very probably stays 1080p-sized at 720p (to confirm on hardware).
- `tnr_refFrame_format` (YUV_REG_9 bits 17-18) comes from the vendor tuning file; its meaning is unknown.
- ISR: `TNR_DMA_OVERFLOW` clears TNR and the 3A loop re-arms it (~4924-4935, 8463-8467). `_3dnr_reset` is dead code;
  `_3dnr_noref` gates TNR.
- Memory: capture buffers 3 x (sizeimage + 345600 + 4096) = 3 x 3379 KiB at 1080p, 3 x 1692 at 720p, 1 MiB aligned
  (`CONFIG_CMA_ALIGNMENT=8`). Default CMA `cma=18M` comes from the **U-Boot command line** (cannot be changed).
  Encoder area 12288 KiB, pool 9600K, 2688 KiB tail (patch 0015, reusable). R9-01 with `cma=24M`: MemAvailable −5.6 MB,
  no CPU or frame cost. Today MemAvailable 22-23 MB, CmaFree ~5.9 MB.
- Budget: 1080p + reference in 18 MiB: zero spare 1 MiB slot; 720p + reference: ~6 MiB spare, ~1 MiB net RAM cost.

**Design.**
- `ak39_vi.nr3d` becomes a 0644 `module_param_cb`: writing 1 before the first stream allocates the reference and clears
  `noref`; 0 sets `noref` (memory kept until reboot). Default 0. `autorun-linux66.sh` writes it from `boot.conf`
  `NR3D=1` before `tc100_rtsp` starts (single source; remove the dead NR3D lines of `isp_tune.conf.dist`).
- `program_ref()` programs CROP_W x CROP_H and refuses (noref) if the allocation is smaller.
- A 0444 `ak39_vi.nr3d_overflow` counter (ISR); under `guard=1` a fill pattern / high-water mark of the reference.
- **1080p without touching U-Boot**: the extra memory cannot come from `cma=` (command line). Candidates, in order:
  (a) a dedicated *reusable* CMA region in the device tree (like the encoder area of patch 0015): movable pages use it
  while 3D-NR is off, so the off case costs almost nothing; needs a free physical range (check the map: kernel,
  initrd at 0x81000000, encoder area 0x81800000, CMA 0x82c00000, the uImage load address 0x82000000 is free after boot);
  (b) the UV plane from the encoder area's 2688 KiB tail (cross-driver helper); (c) fall back to 720p only.
  Any memory-map change is a kernel change: SD kernel first, owner present, read-back review before any flash.

**Measure first (SD kernel)**: high-water mark of the reference at 1080p and 720p; `cma: Reserved` address/size and
CmaFree/MemAvailable per mode; ten stream restarts with the reference allocated; night noise with IR, NR on/off;
2 h H.265 soak.

## 3. Echo cancellation (`[audio-aec]`)

**Facts.**
- Capture: 8 kHz mono S16_LE, period 256 frames (32 ms) (`acap.c:62-71`, patch 0007 ~2675); 300 ms start delay.
- Playback is not in `tc100_rtsp`: `talk.c:111,147` pipes decoded A-law to `sh speaker-play.sh -` which runs
  `aplay -D plughw:0,0 -r 8000 -c 1` (`scripts/speaker-play.sh:44`); up to 0.75 s pipe backlog. Push-to-talk and sounds
  never pass through `tc100_rtsp` (`upload_audio.cgi`).
- No audio threads: `aud_pump()` and `talk_rtp()` run in the main loop. Mic and speaker state meet at
  `adsp_sample(&aud_dsp, s, spk)` (~2093); the duck is a full mute (`adsp.c:77-83`).
- Clocks (patch 0007 ~805-865): the ADC uses OSR 256 only, the DAC chooses from {256, 272, 264, 248, 240, 136, 128, 120}:
  both divide the same PLL but reach slightly different rates (0.16 % at a 480 MHz source, ~0.7 % at 120 MHz; read
  `actual sample rate` in dmesg). An adaptive filter cannot converge through a fixed skew without resampling.
- Build: musl, `-Os -mfloat-abi=soft`, integer only. No SpeexDSP / WebRTC DSP in Buildroot.

**Design.** Own fixed-point NLMS (256 taps, Q15, ~2 KB code, ~18 KB RAM, ~6-12 % CPU only while a client talks) plus
residual suppressor; not SpeexDSP (more flash/CPU, does not solve skew or delay).
- `tc100_rtsp` plays talk sessions itself on `/dev/snd/pcmC0D0p` (stereo S16_LE, `apb.c`) so it knows what was written
  and how much is queued; `speaker-play.sh -hold` keeps the lock, volume and amplifier and waits on stdin.
- Skew: open playback at the ADC rate when the DAC can reach it, else resample the far end (linear) to the measured
  ratio; the reference is the written samples.
- Alignment: bulk delay = playback queued + capture unread + constant D0 (measured); re-align on xrun.
- Order in `aud_pump`: high-pass, AEC, residual suppressor, AGC. Double talk: Geigel-style freeze with 100 ms hold;
  AGC gain rise frozen while the far end is active. Suppressor 0 to −18 dB by reference/error ratio, 150 ms hangover.
- Switch `RTSP_AUDIO_AEC=0` (default) in `rtsp.env`; 0 = today's `aplay` + duck. Push-to-talk and sounds keep the duck.
  If the playback device cannot be opened, fall back to `aplay` + duck.
- Host test `test_aec.c`: synthetic far end through a 20 ms decaying impulse response + 40 ms bulk delay + 5 % cubic
  distortion: ≥ 20 dB echo reduction after 2 s single talk, < 3 dB near-end loss in double talk, re-convergence after a
  delay jump, a skew case that fails without resampling and passes with it.

**Measure first (camera)**: dmesg actual rates; a probe file (1 s silence, 5 clicks, 5 s noise at −12 dBFS, 5 s speech)
played with `speaker-play.sh` while `arecord -D hw:0,0 -f S16_LE -r 8000 -c 1` records, at volumes 50/90/100 (RTSP
service stopped, restarted with the same arguments): peak < −3 dBFS, impulse response length, click-spacing drift,
offline echo reduction with `test_aec`. Prerequisite: the end-to-end talk test (F1).
