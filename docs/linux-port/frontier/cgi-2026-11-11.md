# Dossier `cgi` — vérification de la réponse du 2026-11-11

Réponse du modèle : [cgi-2026-11-11-reponse.md](cgi-2026-11-11-reponse.md). Chaque constat a été vérifié dans le code
complet et, quand c'était possible, reproduit dans busybox ash 1.36 (le shell de la caméra). Tests :
`tests/test_cgi_hardening.py` (chaque correctif retiré fait échouer un test).

| Constat | Verdict | Preuve et suite |
|---|---|---|
| C3 / H3 — un GET qui modifie passe sans garde | **Confirmé, corrigé (le plus grave)** | `action.cgi` n'appelait que `csrf_guard`, qui laisse passer tout GET : `GET action.cgi?cmd=reboot` redémarrait la caméra, donc une balise image sur un autre site suffisait avec la connexion enregistrée du navigateur. Désormais seules 18 commandes de lecture répondent à un GET (la liste de `docs/api.md`) ; les autres reçoivent `405`. Toutes les modifications de l'interface passent déjà par POST (`csrfFetch`) ; un test vérifie que chaque lecture GET des pages est dans la liste. Sans `REQUEST_METHOD` (scripts, tests) : inchangé. |
| C1 — noms de fichiers développés dans l'analyse | **Confirmé, corrigé** | Reproduit : `QUERY_STRING='a*'` donnait `F_abc` avec un fichier `abc` dans le dossier courant, et `/proc/*/*/*` faisait parcourir `/proc`. `set -f` pendant la boucle, `set +f` après. |
| C9 / H1 — échappement de l'`eval` | **Correct ici, simplifié quand même** | Busybox 1.36 double bien la barre oblique inverse. La valeur ne fait plus partie de la chaîne évaluée (`eval "F_${name}=\$value"`) : plus d'échappement à réussir. Testé avec `$(…)`, accents graves, guillemets et `\`. |
| C2 / H2 — jeton CSRF vide accepté | **Confirmé, corrigé** | Si le jeton ne peut pas être fabriqué, un POST sans en-tête passait (comparaison de deux chaînes vides). Un jeton vide est maintenant refusé, et sans `hexdump` le jeton vient de `/proc/sys/kernel/random/uuid` (32 chiffres hexadécimaux, sans fork) avant le repli `md5sum`. |
| C7 — `sanitize_int_range` laisse passer un nombre géant ou `08` | **Confirmé, corrigé** | Reproduit : `99999999999999999999` ressortait tel quel (`out of range`, code 2) ; `08` casse un `$(( ))`. Dix chiffres ou plus : valeur de repli ; zéros de tête retirés. |
| C6 / H4 — borne de 64 Ko contournable | **En partie** | `[ 4000000000 -gt 65536 ]` marche (entiers 64 bits) ; au-delà de 2^63, le test échoue mais `head -c` refuse aussi le nombre : corps vide, pas de lecture illimitée. Corrigé quand même : six chiffres ou plus = 65536. |
| C5 — corps lent | **Corrigé** | `timeout 10 head -c …` : une connexion qui annonce plus qu'elle n'envoie ne retient plus un shell. |
| C8 / H5 — import : chemin et valeur | **Chemin : écarté. Valeur : un trou trouvé à côté** | Le chemin vient seulement de la table fixe des lignes (`_ce_build_rows`), jamais du JSON ; les valeurs doivent être imprimables (`[:print:]`), donc ni saut de ligne ni tabulation. **Mais** en suivant sa piste (« les fichiers chargés par `.` »), `NOTIFY_UPLOAD_AUTH` était écrit entre guillemets doubles dans `notify.conf`, que `notify.sh` charge avec `.`, et son type `credential` acceptait `$`, l'accent grave et `"` : un import pouvait y mettre `$(commande)`, exécutée en root à la notification suivante. Type passé à `ntfy_auth` (refuse `\ $ ` ; & \| < > " '`), à l'export comme à la vérification. Les autres valeurs entre guillemets doubles de fichiers chargés par `.` ont des types qui refusent déjà ces caractères ; les guillemets simples refusent `'`. |
| C4 — décodage `%XX` coûteux avant les gardes | **Accepté, non corrigé** | Un fork par `%XX` : un corps de 64 Ko encodé coûte des dizaines de secondes. La requête passe d'abord par l'authentification du serveur web (httpfront), donc il faut un utilisateur connecté. À reprendre si on veut une borne par valeur (attention à `configeditor.cgi`, qui envoie des fichiers entiers). |
| C10 — limite de débit sans verrou | **Accepté, faible** | Des requêtes parallèles comptent moins que la réalité ; sans conséquence de sécurité (authentification avant). |

Les contrôles sur caméra proposés par le modèle (C3 : `curl -i "…/action.cgi?cmd=reboot"` → `405` attendu après
installation ; C1 : temps égaux avec et sans `?/proc/*/*/*`) sont à faire à la prochaine installation de DEV.
