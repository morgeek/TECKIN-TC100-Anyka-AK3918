# Audit of 2026-11-06: flash size, Wi-Fi losses, features, hardware headroom

Asked by the owner on 2026-11-06 after the rc30: find what can shrink the SPI flash image (rewrites in C or another
language included) **without losing a feature or breaking anything**, what can still be improved in features and
hardware use, and solve the Wi-Fi losses **without ever losing the connection to the camera** (no serial console).
Everything here is for the implementer to explore; each item has a state, a gain, a risk, and a first step. Nothing was
changed on a camera. Figures marked EST are estimates; the others were measured on a PC (squashfs built in Docker with
the build's own options, ARM programs cross-built like CI).

Rules that apply to every item (AGENTS.md): no U-Boot, `boot`, `mac` or `env` change; one kernel change per flash
write, owner present, size and checksum checked before `flashw`; a `boot.conf` switch (default = today's behaviour)
for anything that changes behaviour; a `test-queue.md` entry in the same commit; `sh tests/docker/local-ci.sh` before
pushing.

The French list `a-faire-implementeur.md` points here (section « Audit 2026-11-06 »).

## W. Wi-Fi losses (item #9 of the list, rc27/rc28 field data)

**Facts established by the audit** (code + field measurements):
- Driver: mainline `rtl8xxxu`, built in (`patches/kernel-6.6/defconfig_cma` `CONFIG_RTL8XXXU=y`), firmware
  `rtl8188fufw.bin` built in; patch 0004 only adds EP0 write blocks and retries. USB host: the vendor-derived driver of
  patch 0003 (about 600-660 USB interrupts/s while streaming, PIO, DMA path unused).
- **Not** power saving: `iw ... get power_save` measured `off` on both cameras; `rtl8xxxu` does not do PS (H).
- **Not** USB autosuspend: `# CONFIG_PM is not set` (`defconfig_cma` l. 373). Do not turn it on.
- **Not** background scanning: no `bgscan`/`autoscan` in any generated `wpa_supplicant.conf`; `wifi-roam.sh` scans only
  below -75 dBm (the cameras sit at -25 and -50 dBm). **Not** the country: unchanged with `WIFI_COUNTRY=FR`.
- **Decisive:** pings are lost while `iw` reports **0 tx retries and 0 tx failures**, without disassociation: the
  receive path (rtl8xxxu RX over the USB host) or a stall of the camera itself, not the radio.
- The loss meter itself is weak: 2 pings every 180 s, `-W 1`; 100 % loss of a sample = 2 packets in ~2-3 s.

**Safe-change design** (for the day a runtime Wi-Fi change is worth trying, e.g. a driver parameter writable in
`/sys/module/rtl8xxxu/parameters/`): a new `scripts/wifi-try.sh <change> [window_s]` with a whitelist of changes (no
free-form command), refuses when the rescue AP is up or the router does not answer, records the previous value, applies
the change, and a detached watcher pings the router every 5 s: **reverts after 3 misses (~15 s)** — well before
net-guard's repairs (2 min) and reboot (15 min) — and **reverts at the end of the window unless the tester wrote
`/tmp/wifi-try/confirm`** over ssh. RAM only, a reboot also reverts. Only after validation: a `WIFI_TUNE_<NAME>` key in
`boot.conf` (absent = today), applied from `v3/autorun-linux66.sh`, checked in `scripts/config-transaction.sh`.
Never a "try" for anything that takes the link down (wlan0 down/up, `wifi-apply`, chip power cycle, USB unbind): owner
present only. Do not weaken net-guard: it stays the safety net. Tests: `tests/test_wifi_try.py` in the style of
`tests/test_wifi_roam.py` (revert at window end, confirm, revert on loss, refusals, whitelist).

## S. Flash size (stack partition 2,830,336 B; the only partition under pressure)

**Owner's decisions (2026-11-06) and state:** S1 jq removed everywhere — **done** (`[flash-nojq]`); S1b `.gz` for the five big web files only — **done** (`[flash-gz]`); S3 monvifd out of the flash in rc31, SD package keeps it — **done** (`[flash-nomonvifd]`); S5 minify JS/HTML only, never the shell (readable over ssh) — **done** (`[flash-minify]`); S2 shell minification — **not wanted**; S7 built-in sounds as A-law — **done** (`[flash-alaw]`); S6 Bulma — rc32 (decided); S4 CA bundle — not asked. Measure each in the CI log line `stack.sqfs: N bytes`.

Measured: the git-side part of the stack (everything but `ext/`, which comes from the Buildroot base) is **1,064,960 B**
as built today; **778,240 B** without the `.gz` copies. The rest of the image (~1.3-1.5 MB EST) is `ext/` (curl, jq,
hostapd, iw, dropbear, libasound, mbedTLS, CA bundle...). The initrd has ~0.98 MB free in its own region and cannot give
it to the stack (that would need an env change: forbidden); the kernel has ~110 KB free in its 2 MiB.

**Rewriting shell in C, Rust or Zig is not a flash saving.** xz compresses shell ~3.8x (`state.cgi` 68,648 → 16,416 B)
but ARM code only ~2.3-2.5x (`tc100-onvifd` 46,152 → 18,452 B); C code is ~0.3-0.5x the bytes of the shell it replaces,
so the flash result is even within ±20 %. The gain of C is **CPU and RAM** (no `ash` fork/exec per request: item 55,
R17 slow pages). Rust/Zig would add a CI toolchain for no size gain: stay with C.

Taken together S1+S1b+S2+S3+S5+S6 bring the git-side image from ~1.06 MB to ~0.55-0.6 MB (EST, the savings overlap),
plus jq's share of `ext/`. First action of the implementer: in a CI artifact, `unsquashfs -lls stack.sqfs` and the
`stack.sqfs: N bytes` line, to replace the `ext/` estimates by real numbers.

**Do not:** move `wpa_supplicant` out of the initrd (Wi-Fi must come up without the user space); put `hostapd` or
`curl` on the SD card (wizard and rescue AP on a camera without a card; curl is the only HTTPS client); raise the
squashfs block size; make `.gz` files at boot in RAM; replace curl or the TLS stack for size; remove
`scripts/auto-night-daemon.sh` or `scripts/button-watch.sh` (workers of `tc100-supervisord`: item 58.2 is wrong while
`scripts/supervisor.sh` runs them); delete `mqtt-bridge.sh`; batch a kernel change with user-space trims in one flash.
