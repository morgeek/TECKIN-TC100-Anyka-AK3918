# Audit of 2026-11-16: kernel, streaming, network daemons, flash chain, web layer, CI and docs

Asked by the owner on 2026-11-16 ("audit complet du projet"). Seven read-only audits ran on `main` at `6554f33`
(3.0.1), one per area; the confirmed findings were fixed the same day on `audit-1116-*` branches. Every fix of the
kernel, flash/boot, streaming and network areas was then read by the `reviewer` agent and corrected where it found a
problem. The commits carry the prefix `[audit-1116]`. **Nothing was run on a camera**: the camera tests are the
`AUDIT-1116-*` entries of [test-queue.md](test-queue.md).

Status words: **fixed** (in `main`, waiting for its camera test), **open** (not changed; reason given), **owner**
(needs a decision or a test by the owner).

## Summary

- No hard-brick path was found. Nothing writes U-Boot, `boot`, `mac`, or the environment outside `stock-hook.sh`.
  Partitions are looked up by name, and `flashw` refuses the read-only ones.
- No memory-safety bug was found in the network parsers: httpfront, onvifd, WHEP (STUN, DTLS, SDP), mDNS, the RTSP
  request parser and the MQTT framing.
- The weak points were the following:
  1. **Recovery paths that did not trigger:**
     - a crash at video start was never counted, so safe mode was never reached;
     - nothing stopped a reboot from cutting a flash write.
  2. **Authentication policy:**
     - the web login lockout could be bypassed;
     - an ONVIF digest could be replayed;
     - ssh was not covered by `NET_LAN_ONLY`.
  3. **Robustness of long runs:**
     - wall-clock timeouts were thrown off by the NTP step;
     - a capture stall went undetected;
     - several kernel races.
